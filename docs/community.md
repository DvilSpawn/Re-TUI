# Experimental community feed

Run `community` to open the opt-in Re-TUI community Activity. Nothing connects on launcher startup. Both F-Droid and Play Store use the same native username/password authentication at `https://irc.kokodoko.cloud/community`; no email, Google sign-in, social provider, Firebase, push, analytics or CAPTCHA dependency is added.

Use `/register` for public registration, or `/login` for an existing username. Passwords and registration confirmation are entered only in masked, dedicated fields, not commands or launcher history. Registration is not sign-in: the app authenticates and validates a returned token before saving a session. A session token is saved encrypted; raw passwords are not saved. There is **no forgotten-password recovery**. Register a new username to continue: it is a separate identity; the old username is not reclaimed and ownership/history do not migrate automatically.

## Input

Plain text posts with Send or Enter; Shift+Enter inserts a newline. `exit` is a message, `/exit` leaves, and `//exit` posts `/exit`. Unknown slash commands are rejected locally. `settings; reboot` is literal text, never launcher or shell input. Received text is selectable but links do not automatically open or execute.

Local commands: `/help`, `/refresh`, `/older`, `/login`, `/register`, `/logout`, `/exit`, `/report <full message ID>`, `/block <username>`. Blocking is local and account-scoped; repeat to unblock. Reports display success only after server acceptance. Message limits: 500 Unicode code points and 2000 UTF-8 bytes.

## Storage and delivery

The local cache holds at most 200 message bodies. Loading `/older` moves this bounded window toward earlier history; ordinary timer polls recheck it without forcing a scroll. Newer arrivals outside that window are announced in the unread header using at most 50 body-free ID/author metadata entries and a separate newest-observed cursor. `/refresh` explicitly returns to the latest window and scrolls to its newest messages; a successful own post immediately fetches the latest peer page, retains its canonical acknowledgement and is marked read. If that follow-up fetch fails, delivery remains successful and the status separately labels the feed stale; the post is not resent. The history/latest mode and arrival observations survive recreation. Account token, cache, local blocks, read markers and draft are encrypted with an AndroidKeyStore AES-GCM key in `noBackupFilesDir/community/state.bin`, outside launcher preset/personal exports and Android backup. Logging out clears all account state; switching accounts does not share cache or draft. Leaving an unsent draft offers Keep, Discard or Cancel. Nothing posts automatically on restoration.

A post gets a persisted UUID and immutable body before sending, separately from the editable draft. A retained attempt is treated as potentially delivered, including after network failure, any HTTP 5xx response, or lifecycle cancellation. Submitting again looks up that original author/UUID/body **before** retrying; a failed lookup keeps the identity and sends no retry POST. A successful empty lookup allows a same-UUID retry, but a later rejection still cannot prove the original attempt never committed. Only a first-attempt validation HTTP 400 (after successful empty reconciliation) or HTTP 429 releases the attempt marker without discarding the draft. A matching canonical record completes delivery; neither a duplicate HTTP 400 nor a gateway failure alone proves delivery or rejection. A newer editable draft is never sent under the original UUID, and completion preserves it across recreation. Submit again after completion to send the newer draft. HTTP 401/403 clears private account state under the logout policy, without claiming that a potentially committed post was retracted. Discarding or logging out does not retract a post that may already have reached the server.

Polling runs only while the Activity is visible, normally every 15 seconds, without overlapping requests. Pause cancels requests and polling, permanently invalidating that operation before any later chained request or checked-ID chunk. Reentry starts a fresh operation without reviving the cancelled one; a cancelled post keeps its pending UUID/body for manual reconciliation. Errors retain only unexpired stale cached history, with backoff. A separate foreground callback on the existing UI handler expires cached/rendered bodies and arrival metadata at their server `created` timestamp plus 24 hours, even while refresh is failing, backed off or busy. It stops on pause and rechecks on resume; it is not a background service. Exact age >=24 hours, invalid timestamps and future-dated records are excluded. `updated` never extends retention. Expiry does not release an uncertain post UUID/body or erase an editable draft. Older body-free arrival metadata without a creation timestamp is discarded rather than kept indefinitely. Refresh rechecks bounded cached IDs so moderation deletions are reflected without treating absence from the latest page as deletion. Expired/revoked sessions clear private account state.

## Pilot limitations

The Android surface remains one general room: no private messages, presence, attachments, read receipts, sockets or background service. Messages are server-readable, **not end-to-end encrypted**. The backend v2 contract expires each general message individually at age **>=24 hours** from immutable server creation in UTC (not midnight or last edit); API reads hide expired/future-dated messages immediately, with physical purge normally every minute. Accounts persist. Accepted reports retain private snapshots of reported text/author and reasons for **six calendar months** after report creation in UTC, with end-of-month clamping, not 180 days; deleting the source message/account does not remove that evidence. Active assigned moderators and loopback administrators can read it.

Backend v2 also provides persistent `bugs`, `features` and `presets` threads/replies and a six-calendar-month private moderator-request queue. Channel/thread UI, `/moderate`, moderator queue UI and reply/resolve workflows are **not implemented in this Android release**. `/report` remains available; it succeeds only on server acceptance and cannot report a source that has already expired.

Local expiry relies on the device wall clock and runs when state is restored, merged, saved or rendered, and while the Activity is visible. An unopened/paused app cannot rewrite its encrypted on-disk cache at the cutoff; it prunes on next access/save. Drafts and immutable uncertain-delivery bodies are separate user-controlled state, not timed chat history. This is not forensic secure erasure of storage, memory, WAL/free pages or provider snapshots. Scheduled whole-database server archives are disabled because they would preserve expired text, but unresolved legacy archives/rollback copies remain retention exceptions; no offsite backup is configured and persistent identities/threads have single-VPS loss risk. See [the backend contract](../server/community/README.md) for policy and operational limits. PocketBase is pre-1.0: this optional experimental feature and its storage/API may change.

Release gates include deployed public-registration rules/rate limits, validated TLS and collection authorization, authenticated two-user live integration, and final release-flavor/device regression checks. Emulator fixture tests do not establish production availability or physical-device compatibility.

`CommunityLiveIntegrationTest` is skipped unless instrumentation receives `-e liveCommunity true`, and is restricted to disposable emulators. It uses the fixed production HTTPS endpoint with ordinary certificate validation and generates credentials only in memory. It emits only its unique temporary usernames/member IDs for operator cleanup; after any run, remove only those exact fixtures and verify their related messages/reports are gone. It respects rate-limit delays with bounded foreground waits.
