# Widgets: match Settings' blur behind system bars

The earlier activity-backing correction did not match Settings. Widgets still applied `RenderEffect` to individual launcher views inside the inset content area, so their blurred output stopped at the status-bar boundary. Settings uses a separate translucent window and Android's blur-behind compositor, which covers the full underlying launcher window, including the status-bar area and launcher foreground effects. Earlier focused tests did not explicitly require visible system bars and missed this visual difference.

Widgets now presents its existing board in an always-expanded translucent window using the same `Custom.Floating` theme and `PanelBackdrop.installWindow` policy as Settings. The theme name does not introduce a floating geometry mode: the window fills the available screen, with no move/resize controls for the outer pane. Native widgets retain their own resizing controls. Only content respects system/cutout/user margins; the blur window starts at screen y=0. The actual board fill, header, controls and widget data remain unchanged.

The launcher stays fully rendered underneath. No launcher background is cleared or window format/flags temporarily replaced. Closing the pane dismisses its window, releases the blur listener and restores the board to its original view parent. Existing manager activity-result routing and widget identities remain intact. Keyboard handling uses the pane's own window token, and its system/IME insets continue through the existing display-margin calculation.

Validation on physical Vivo `10BE1C0FB40006A` / Android 16: **10 checks passed in portrait and the same 10 in landscape**. These cover visible status bars, full-window blur flags/radius, content staying below status/cutout insets, the configured board fill, System Back, unchanged underlying launcher state, blur detach cleanup, Settings, live native resize/cancellation, keyboard clearance, scrolling and chip height, editing/hide/reopen, picker search/Back, recreation and retained bindings, and Space ownership safety. The picker test now waits for the asynchronous provider catalogue to load instead of assuming a one-second delay is sufficient on every phone. The initial broader run passed 9/10 and exposed that premature assertion; the final two runs each passed 10/10.

Screenshots reproduce the old cutoff with visible bars, show the Settings reference, and show the corrected full-window blur. They are from the isolated fixture package with an explicit opaque test board, not a change to the user's theme. Both the board and all margins remain independently configurable.
